# A100 runbook (branch `a100-training`)

Train on the A100 without downloading ERA5 there: copy the exported daily tensor
(2.2 GB) and point configs at it with `data.npy_dir`.

## 1. Export (on the machine that has the netCDF)

```bash
.venv/bin/python scripts/export_training_data.py \
    --config configs/temp_prep_era_anom_30_100ep.yaml --out ../data/era5_npy/amazonia_daily
```

Writes `mn2t.npy`, `mx2t.npy`, `tp.npy` (each (16802, 94, 120) float32, 1980-01-01..2025-12-31,
raw K and mm/day), `times.npy`, `lat.npy`, `lon.npy`, `meta.json`, `SHA256SUMS`. These are the
*raw* daily fields (crop + hourly→daily only). Transforms, train/val split and the per-month
z-score still run inside `Era5Dataset`, so one export serves every experiment. Checked:
the `npy_dir` path gives tensors identical to the netCDF/cache path (train 15 706 days,
val 1 096) for the TP30-cbrt config.

## 2. Copy and verify

```bash
rsync -avP ../data/era5_npy/amazonia_daily/ <a100>:<repo>/../data/era5_npy/amazonia_daily/
# on the A100:
cd ../data/era5_npy/amazonia_daily && sha256sum -c SHA256SUMS
```

If the folder lives elsewhere, change `NPY_DIR` in `scripts/make_a100_configs.py` and rerun it.

## 3. Environment

`uv sync` installs torch cu130. If the A100 driver is older than CUDA 13, install the cu128 wheels
(`uv pip install torch==2.11.0+cu128 torchvision==0.26.0+cu128 --index-url https://download.pytorch.org/whl/cu128`).

## 4. Run

```bash
setsid scripts/run_a100_chain.sh > logs/a100_chain.log 2>&1 &   # all runs, priority order
setsid scripts/run_a100_chain.sh t15_s1 t15_s2 > logs/a100_chain.log 2>&1 &   # a subset
kill -- -$(cat logs/a100_chain.pid)                                # stop everything
```

## 5. Runs (`configs/a100/`, generated by `scripts/make_a100_configs.py`)

All: base = `configs/temp_era_anom_15_100ep.yaml`, bf16, val years 2023–2025, best checkpoint by
val MSN, no early stopping. Batch 512 runs use **no micro-batching** (true full-batch BatchNorm).

| Config | What | Question |
|---|---|---|
| `t15_s{0,1,2}`, `t30_s{0,1,2}` | replication, 3 seeds | Which regimes / ENSO links survive across seeds? (paper needs it) |
| `t60_b1024`, `t100_b1024` | over-clustering, batch 1024 (micro 512), 200 epochs | Do finer prototypes, merged afterwards, give more pattern separation (η² pattern, partial test)? |
| `t30_nomean` | domain mean removed after the z-score | Do pure *pattern* regimes carry ENSO signal beyond the level? |
| `p30_daily_raw` | daily tp, z-score like temperature | precip-only control |
| `p30_daily_cbrt` | daily tp, cube root → z-score | fixes the heavy tail (z kurtosis 42 → 1.5) |
| `p30_roll30` | trailing 30-day tp sum per pixel, daily samples | accumulated precip (z skew 0.7, kurtosis 1.5 without a transform) |
| `p10_monthly` | calendar-month tp sum, 516 train months, batch 128, 500 epochs | monthly precip regimes; small-data check |

New config keys (all optional, defaults reproduce earlier runs): `data.npy_dir`,
`data.temporal_agg` (`{kind: rolling, window: N}` or `{kind: monthly}`; tp summed, temperatures
averaged), `data.remove_spatial_mean`, `meta.seed` (default 0, also seeds the sampler).

Notes:
- `p10_monthly` gives one cluster per month, so occupancy analysis becomes "label per month"; the
  analysis notebooks need adapting. `p30_roll30` keeps daily occupancy but neighbouring days share
  29/30 of their window.
- If the A100 has 40 GB, set `micro_batch_size: 256` for batch 512 (exact gradient caching).
